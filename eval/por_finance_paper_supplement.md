## Why the Finance Environment is a Strong Contribution

The core PoR paper demonstrates defense against explanation poisoning in the **CyberDefend** environment (discrete tool-use, 40 nodes).

The Finance environment adds three orthogonal axes of novelty:

| Axis | CyberDefend | Finance (Hedge Fund) |
|---|---|---|
| **Agent reasoning structure** | Rule-based incident response  | Market-regime-conditioned portfolio decisions |
| **Backdoor mechanism** | Single-target sabotage (tool 39) | Economic sabotage (market dump a_35) via macro trigger (VIX spike) |
| **Topology complexity** | 40 discrete tools | 11×3 sector APIs + 3 exec actions = 36 nodes with cross-sector correlations |
| **Privacy** | None | (ε,δ)-DP guarantee via DP-SGD + RDP composition |
| **Interpretability** | None | Cross-sector Transformer attention maps, regime-conditioned |

**Key claim for paper Section 5 (Finance Generalization):**
> *PoR's topology-based defense generalizes beyond rule-based agent workflows to complex, market-regime-conditioned sequential decision processes. The Transformer encoder's attention weights provide post-hoc interpretability that is more informative under PoR-filtered FL than under undefended FedAvg.*

## Theorem 1: Topology Irreducibility (Finance Variant)

**Informal Statement:**  
No adversarial agent can execute economic sabotage action `a_35` (Market Dump) under trigger `t` and simultaneously maintain an execution graph `G(π_mal)` that is indistinguishable from the honest consensus `G_consensus`.

**Formal Statement:**

Let:
- `G_consensus = (V, E_hon)` be the canonical honest execution graph where `E_hon = {(i, i+1) | i ∈ [0,31]} ∪ {(32, 33)}`
- `π_mal` be any backdoor policy that satisfies: `P[a_35 | obs_t = trigger_t] > 0.5`
- `G(π_mal) = (V, E_mal)` be the induced Markov execution graph extracted from `π_mal`'s trajectories

**Theorem:**  
For any `π_mal` satisfying the above, the Jaccard edit distance satisfies:

```
JED(G(π_mal), G_consensus) ≥ ε_min > 0
```

where `ε_min = 1/|E_hon| = 1/33 ≈ 0.030` (one mandatory edge difference to route to a_35).

**Proof Sketch:**

1. `E_hon` contains no edge `(i, 35)` for any `i ∈ V` (the sabotage action is unreachable in honest policy).
2. Any `π_mal` with `P[a_35 | t] > 0.5` must have at least one edge `(j, 35) ∈ E_mal` for some `j`.
3. Since `(j, 35) ∉ E_hon`, we have `E_hon △ E_mal ≥ 1` (at least one edit required).
4. Therefore `JED = |E_hon △ E_mal| / |E_hon ∪ E_mal| ≥ 1 / (|E_hon| + |E_mal|) ≥ 1/(33 + |E_mal|) > 0`.
5. In practice, routing to `a_35` requires *removing* honest edges (queries that weren't made) *and* adding the sabotage edge — the real-world ε_min is much larger (empirically measured in `eval/topology_irreducibility.py`). ∎

**Contribution:**  
This result makes the PoR defense *principled*: it is not a heuristic threshold but a mathematically grounded lower bound on the structural divergence of any successful backdoor.

## Theorem 2: PoR-Filtered Training Produces More Interpretable Policies

**Statement (informal):**  
After `T` FL rounds with PoR filtering, the Transformer attention entropy `H(A_t)` is lower (more concentrated) than under undefended FedAvg, where `A_t` is the attention distribution at round `t`.

**Empirical operationalization:**  
See `eval/attention_visualizer.py`. The attention entropy:

```
H(A) = -∑_{i,j} A_{ij} * log(A_{ij})
```

is expected to be lower for PoR-trained models because:
- PoR rejects clients whose execution topologies are diffuse (high entropy transitions)
- Only clients with focused, sequential sector analysis pass the GED gate
- This selection pressure propagates to the global model via FedAvg
- Result: the global Transformer learns to attend sharply to economically relevant sector pairs

## Formal Privacy Guarantee (DP-SGD RDP Composition)

Each client's PPO update uses DP-SGD with:
- Clipping norm `C = 1.0`
- Noise multiplier `σ = 0.3`  
- Sampling ratio `q ≈ 0.1`

By the Rényi Differential Privacy (RDP) guarantee for the Sampled Gaussian Mechanism (Mironov et al. 2017, 2019):

For a single DP-SGD step:
```
ε_RDP(α) = α·q² / (2·σ²)   [leading term]
```

After `T = rounds × steps_per_round × ppo_epochs` total steps, by RDP composition:
```
ε_RDP_total(α) = T · α·q² / (2·σ²)
```

Converting to (ε, δ)-DP:
```
ε(δ) = min_{α>1} [ ε_RDP_total(α) + log(1/δ)/(α-1) ]
```

Run `eval/dp_privacy_accountant.py` to compute the exact guarantee for your training configuration.
